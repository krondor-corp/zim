## Goal
Define the cryptographic identity and remote key-control model for a read-only web mirror gateway (zim-hub) that uses Google auth to unlock access to a password-protected private key.

## Acceptance
- [ ] Identity flow is described end-to-end: Google auth, local credential state, key unlock, remote peer authorization.
- [ ] Threat model and security constraints are documented for private key custody and serving behavior.
- [ ] A concrete integration sketch references existing modules in `crates/common`.

- Full implementation of auth providers.
