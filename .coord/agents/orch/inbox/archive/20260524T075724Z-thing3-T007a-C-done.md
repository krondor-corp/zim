## T-007a-C done — sync_provider shutdown leak fixed

Smaller surgical change than I expected. The structural shape from thing2's audit memo (§P-2) was the right diagnosis: `State::from_config` was spawning the worker bare with the JoinHandle dropped on the floor, and the worker had no shutdown signal so it lived until process exit.

### What changed

**`crates/zim-peer/src/sync_provider.rs`**
- `run_worker` now takes a `mut shutdown_rx: tokio::sync::watch::Receiver<()>` parameter.
- The `tokio::select!` loop gains a `_ = shutdown_rx.changed() => break` arm, placed first so a shutdown that races with a queued job wins.
- Comment block explains the in-flight ping handling (semaphore drops; spawned ping tasks are detached and torn down at process exit).
- Doc/example block updated to show the new spawn signature.

**`crates/zim-peer/src/service_state.rs`**
- `ServiceState::from_config` no longer spawns the worker. Returns `Result<(Self, JobReceiver), StateSetupError>` so the caller owns the receiver and the worker's lifecycle.
- Comment block where the spawn used to be explains the change + ties to T-007a-C.

**`crates/zim-peer/src/process/mod.rs`**
- `create_state` helper signature updated to return the tuple.
- `start_service` spawns the worker as a managed task via the same `handles.push` pattern as peer/api/gateway, with `shutdown_rx.clone()`. The worker now drains within the daemon-wide 30s shutdown deadline, same as the other services.

**`crates/zim-peer/src/lib.rs`**
- `mod sync_provider` flipped from `pub(crate)` to `pub` so external embedders (zim-hub, future hosts) can call `run_worker` directly.

**`crates/zim-hub/src/main.rs`**
- Update `ServiceState::from_config` call to handle the tuple return.
- New `"sync"` Service alongside `"http"` and `"peer"`, calling `zim_peer::sync_provider::run_worker(peer, stream, shutdown_rx)` under the existing `ShutdownHandle`. zim-hub's embedded peer now also gets the leak fix as a free side-effect of the structural change.

### Verified

**Regression test** in `sync_provider.rs` (`#[cfg(test)] mod tests`): constructs a real `Peer` via `PeerBuilder::new()` with `MemoryBucketLogProvider`, spawns `run_worker`, fires the shutdown channel, asserts the worker exits within 5s. Passes — the test would hang indefinitely against the old code.
