## T-016a done

Per your autonomy grant, slotted before M2b. Scope ended up a hair bigger than "in zim-fs only" because `Share::new_mirror` had callers in zim-protocol + zim-fs (and a test). All clean.

### What landed

**`crates/zim-fs/src/fs/principal.rs`**
- New `PeerType { Owner, Mirror, Anonymous }` enum + `Display` impl. Comment ties it explicitly to T-016 (wire-level identification, distinct from `PrincipalRole`).

**`crates/zim-fs/src/fs/manifest.rs`**
- Deleted `Share::new_mirror`.
- New `mirrors: Vec<PublicKey>` field on `Manifest` with `#[serde(default, skip_serializing_if = "Vec::is_empty")]` for wire backcompat (existing manifests deserialize with empty `mirrors`; manifests with no mirrors serialize without the field).
- Initialized `mirrors: Vec::new()` in `Manifest::new`.
- Four new methods:
  - `mirrors() -> &[PublicKey]`
  - `add_mirror(pk) -> ()` (idempotent)
  - `remove_mirror(pk) -> bool`
  - `classify_peer(pk) -> PeerType` (shares→Owner, mirrors→Mirror, else Anonymous)
- Updated `add_share` doc to drop the `Share::new_mirror` reference.

**`crates/zim-fs/src/fs/mod.rs`** — re-export `PeerType`.

**`crates/zim-fs/src/fs/fs_inner.rs:367`** — `Fs::add_mirror` now calls `manifest.add_mirror(peer)` instead of `manifest.add_share(Share::new_mirror(peer))`. Public API surface unchanged.

**`crates/zim-protocol/src/peer/sync/sync_bucket.rs`**
- Removed unused `use zim_fs::Share;` from the test module.
- Rewrote `test_verify_author_rejects_non_writer` → `test_verify_author_rejects_mirror_peer`. The old test path (mirror with role=Mirror in shares → `AuthorNotWriter`) is no longer reachable; mirror peers are now in `mirrors`, not `shares`, so `verify_author` rejects at the prior step with `AuthorNotInShares`. Comment in the test explains the semantic shift.

### What I deliberately did NOT delete

- **`PrincipalRole::Mirror` enum variant** stays. T-016a spec was "delete `Share::new_mirror`", not "delete the enum". With no constructor for Mirror shares, the variant is now dead in practice — but `fs_inner.rs` lines 302/1400 still have match arms (defensive `unreachable!`-style fallbacks), and zim-peer's `share.rs`/`stat.rs`/`shares.rs` have display branches. A follow-up cleanup pass could delete the enum variant + all dead branches; out-of-scope for T-016a per the task notes.
- **`AuthorNotWriter` error variant** stays in `ProvenanceError` — defensive, fires only if someone constructs a Mirror share manually (which `Share::new_mirror`'s deletion makes extremely unlikely).
