## Goal
Produce a written audit of the current `crates/daemon/` design and ergonomics, then propose concrete improvements. Design-only — output is a memo, not code changes. Implementation (if approved) will be spawned as a separate task assigned to a worker.

References (for inspiration, not binding patterns):
- https://github.com/krondor-corp/jig/blob/main/crates/jig-cli/src/daemon/actors/actor.rs — actor-style daemon ergonomics.
- https://github.com/krondor-corp/pack — `runtime::Service` trait, handler-per-file, scoped events; consider whether these fit Zim's daemon, but no obligation to adopt.

Pack is the *aesthetic* reference for Zim, not the architectural one — see `broadcast/20260524T015636Z-pack-design-language.md`. Recommend what makes the daemon better on its own merits; cite either reference if it helped.

## Acceptance
- [ ] Map the current daemon architecture: process model, command surface, HTTP server wiring, FUSE feature gate, database integration, lifecycle.
- [ ] Identify ergonomic pain points (boilerplate, fragmented state, CLI/HTTP duplication, lifecycle/shutdown, error propagation).
- [ ] For each pain point: one or two suggested improvements with rationale. Reference jig or pack where relevant; do not force-fit either pattern.
- [ ] Prioritized list of suggested improvements (target shape, not migration steps — clean-break tenet applies).
- [ ] Output lands as a memo in `.coord/broadcast/` or as a doc draft for thing4 to apply to `docs/architecture/`.

## Out of scope
- Any code changes (this is design-only).
- Backwards-compatibility or migration plans (clean-break tenet, see broadcast 20260524T014147Z).
- Daemon feature additions unrelated to ergonomics.
