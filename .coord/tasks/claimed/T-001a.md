## Goal
Land the server-side identity surface in `zim-hub`: Google OAuth callback, signed session cookies, `identity_keys` SQLite table + migrations, REST endpoints for the browser to fetch/store its encrypted blob, Datastar pages for login/enrol/unlock. See T-001 `## Proposal (20260524T050253Z thing5)` for full design.

## Acceptance
- [ ] Cargo deps added: `oauth2`, `tower-cookies`, `jsonwebtoken`, `argon2` (host-side validation only).
- [ ] `src/auth/google.rs` (login + callback handlers, JWKS verification, `sub` extraction).
- [ ] `src/auth/session.rs` (signed-cookie session, 24h expiry, `data_dir/session.key` auto-generated 0600).
- [ ] `migrations/` with `identity_keys` table per the T-001 SQL schema.
- [ ] REST endpoints: `POST /api/v0/identity/enrol`, `GET /api/v0/identity/blob`, `POST /api/v0/identity/rekey`, `POST /api/v0/identity/rotate`, `POST /api/v0/identity/logout`.
- [ ] Datastar pages: `/login`, `/enrol`, `/unlock`, `/account/password`, `/account/rotate`.
- [ ] **SRI hashes** for `zim_wasm.js` + `datastar.min.js` baked into `base.html` (folded into this task per T-001 open question 5).
- [ ] **CSP** header set: `script-src 'self'`.
- [ ] All four cargo checks green workspace-wide.

## Out of scope
- WASM-side crypto (T-001b, thing5).
- Owner-side viewer authorize CLI (T-001c, thing1).
- Docs (T-001d, thing4).
- Password recovery (explicitly out per T-001 Decision 7).
- WebAuthn / hardware-key unlock (out per T-001 Decision 5).
