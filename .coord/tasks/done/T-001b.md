## Goal
Extend zim-wasm with browser-side identity-key handling per T-001 Decision 4. See T-001 `## Proposal` for full design.

## Acceptance
- [ ] `argon2 = "0.5"` added to `crates/zim-wasm/Cargo.toml`.
- [ ] New `#[wasm_bindgen]` exports:
  - `generateKey() -> Uint8Array` (returns the new public key; private key stored in WASM thread-local).
  - `encryptKeyBlob(password: string) -> { encrypted_blob: Uint8Array, salt: Uint8Array, public_key: Uint8Array }` (Argon2id KEK, ChaCha20-Poly1305 wrap of in-memory secret).
  - `unlockKeyBlob(blob: Uint8Array, salt: Uint8Array, password: string) -> void` (Argon2id KEK derivation, decrypt; on auth-tag failure throws `JsError`; on success loads secret into thread-local for `decryptBlob` consumption).
- [ ] Existing `init` / `loadKeyFromSession` / `decryptBlob` / `clearKey` semantics unchanged.
- [ ] Argon2id params match T-001: `m=19456 KiB, t=2, p=1` (OWASP 2024).
- [ ] Bundle re-vendored: `wasm-pack build crates/zim-wasm --target web --out-dir ../zim-hub/static/vendor/zim-wasm --out-name zim_wasm --release`.
- [ ] README updated with new function signatures.
- [ ] Bundle size delta documented (Argon2id is bigger; T-001 acceptance noted).

### Reuse: `zim_crypto::Secret` for the KEK wrap

The KEK (32-byte Argon2id output) is wrapped in a `Secret` via `Secret::from_slice(&kek)` and then `Secret::encrypt(secret_key_bytes)` does the ChaCha20-Poly1305 + nonce-management. No new crypto code in zim-crypto required, no second AEAD impl, no second nonce surface to audit. T-001 Decision 4 called this out as the reuse pattern; it shipped clean.
