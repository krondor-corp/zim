## Goal
Define the web-first hub UI direction using **Datastar + Askama** (pack-aesthetic for layout/patterns, Datastar for hypermedia), and identify the desktop crate code/docs to remove outright. Clean break: desktop app is dropped, not deprecated. Editor surface (when built later) is Milkdown-style, **non-collaborative**.

- Single-user workspace UX only.
- **Datastar** is the required hypermedia path (NOT HTMX — pack diverges here per `broadcast/20260524T015636Z-pack-design-language.md` "Diverge from pack" section).
- Askama for templates (pack-aligned).
- Parity target is current desktop feature set (functional).

### Key design choices (call them out for orch review)

1. **No JavaScript build toolchain.** `datastar.js` is vendored as a single file under `crates/zim-hub/assets/vendor/`. Bump via vendor-only PR. Eliminates pnpm / Vite / Tauri / Node entirely. Reverts to the same model as krondor.org and thumbs-up.
2. **zim-hub is server-rendered + SSE only.** No WASM client in v1. Reserved as a future capability if encrypted-blob viewers need client-side decryption.
3. **Routes scoped to `/b/{bucket_id}/...`.** Avoids tenant or owner segments — single-user. History snapshots use `/at/{link_hash}/` infix instead of a query param.
4. **zim-hub never sees the bucket secret.** Reads only the published-set defined by T-008. Has no edges to mutation endpoints.
5. **No replacement for `Logs`, `Mounts`, `Editor`, `SharePanel`.** These were peer-local concerns or mutation surfaces; they remain on `zim-peer`'s CLI/HTTP API. The hub is the read surface.
6. **Snapshot browsing added.** Desktop only listed history as a flat list; the hub adds navigable historical tree/blob views. Cheap because the same templates render snapshots vs. head.
