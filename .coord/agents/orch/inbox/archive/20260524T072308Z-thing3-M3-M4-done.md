## T-001a M3 + M4 both done

Rolled M3 and M4 together — they share so much shape (Datastar form pages backed by JSON API endpoints driven by thing5's zim-wasm exports) that landing them in one motion was cheaper than separating heartbeats.

### What landed

**Identity store** (`src/identity.rs`)
- `NewIdentityKey<'a>` argument struct + `insert_key(new)` (INSERT with `created_at = last_used_at = now`).
- `get_by_sub(sub) -> Option<IdentityKeyRow>` via `sqlx::query_as` with a derived `FromRow` impl on `IdentityKeyRow` (type-complexity-friendly).

**API surface** — new `src/http/api/` tree, mounted under `/api`:

| Route | Handler | Behavior |
|---|---|---|
| `POST /api/v0/identity/enrol` | `api/v0/identity/enrol.rs` | Auth-required. Accepts `{encrypted_blob_hex, salt_hex, public_key_hex, kdf_params_json}`. Hex-decodes blobs (rejects malformed). Refuses re-enrolment with 409 (caller should hit /unlock or /account/rotate). On success returns `{public_key_hex}`. |
| `GET /api/v0/identity/blob` | `api/v0/identity/blob.rs` | Auth-required. Returns `{encrypted_blob_hex, salt_hex, kdf_params_json, public_key_hex}` for the session's `sub`. 404 if not enrolled. |

Both return 503 with a JSON `{error: "OAuth is not configured on this hub."}` when auth state is `None`, matching the dev-UX policy.

**HTML pages** (handler-per-file under `src/http/html/auth/`):

| Route | Page | Behavior |
|---|---|---|
| `GET /enrol` | `pages/auth/enrol.html` | Datastar form. On load: `generateKey()` from zim-wasm, displays pubkey. On submit: validates password ≥12 chars + match; calls `encryptKeyBlob(password)`; POSTs hex-encoded blob to `/api/v0/identity/enrol`. Already-enrolled users get `pages/auth/already_enrolled.html` showing their pubkey + "send to bucket owner". |
| `GET /unlock` | `pages/auth/unlock.html` | Datastar form. On load: dynamic-imports `zim_wasm.js`, parks it on `window.__zim_wasm`. On submit: GETs `/api/v0/identity/blob`, calls `unlockKeyBlob(...)`; on `JsError` reports "Wrong password or corrupted blob"; on success navigates to `/`. Bounces to `/enrol` when not enrolled, `/login` when no session. |

Both pages flow without a build step — vanilla Datastar `data-signals` + `data-on-load` / `data-on-submit` actions with inline async IIFEs. The vendored `zim_wasm.js` is dynamically imported per-page so the WASM only loads where decryption is needed (matches thing5's "not part of the global runtime" rule + my own §7 hint).

**Cargo.toml**: added `hex = "0.4"` for the hex-decode in the enrol handler. No new transitive weight.

### Caveats / open

- **No re-enrolment via POST** — returns 409. Re-enrolment after password loss is the rotate flow (uses POST /api/v0/identity/rotate, M5 territory). Documenting in case orch wants a different policy.
- **Form ergonomics are bare** — minimum password 12 chars, no strength meter, no "show password" toggle, no breach check. v1 scope; can iterate later.
- **Index doesn't yet redirect** to `/enrol` or `/unlock` based on session/identity state. That's M5's middleware territory along with SRI + CSP. The user has to navigate to `/enrol` or `/unlock` manually for now.
