## T-001a M2 done — Google OAuth + session middleware

Decided to roll into M2 in the next tick after M1 (consistent with momentum directive and the milestone shape you set). Made the env-var-optional call I flagged in the M1 ack — if you'd rather hard-require the OAuth env vars, easy revert (one match arm in `main.rs`).

### What landed (`crates/zim-hub/`)

**New module `src/auth/`** (handler-per-file split kicked in for `http/html/auth/` too):

| File | Purpose |
|---|---|
| `src/auth/mod.rs` | `AuthState { google, session }` + `from_config` constructor. Returns `AuthSetupError` aggregating google + session setup errors. |
| `src/auth/google.rs` | `GoogleClient` wrapping the typed `oauth2::Client<...>` (factored into a `type OAuthClient = ...` alias to satisfy clippy's `type_complexity` lint). PKCE login + token exchange against `accounts.google.com`. JWKS verification + `id_token` parsing deferred to M2b (currently stubs `sub` from access-token prefix so the session round-trip is testable — flagged clearly in the handler comment). |
| `src/auth/session.rs` | `SessionLayer` over `tower-cookies` signed jar. 32-byte key (actually 64 for `tower-cookies::Key`) persisted at `data_dir/session.key` with 0600 mode. Two cookie types: `zim_hub_session` (24h, the auth state) and `zim_hub_oauth_flow` (10min, the short-lived CSRF+PKCE state during the redirect round-trip). |

**Handlers** (`src/http/html/auth/`):

| File | Route | Behavior |
|---|---|---|
| `login.rs` | `GET /login` | If OAuth configured → redirect to Google. Else → render `pages/auth/login.html` "Not configured" page. |
| `callback.rs` | `GET /callback?code=&state=` | Verify CSRF, exchange code via oauth2, persist session, redirect to `/`. Error path → `pages/auth/error.html`. |
| `logout.rs` | `POST /logout` | Clear session, 307 redirect to `/`. |

**Wired into** `http/html/mod.rs` (merge alongside index/bucket/static). `http/mod.rs` gained `CookieManagerLayer` so request handlers get `Cookies` injected.

**Config** (`src/config.rs`): three new env vars — `ZIM_HUB_GOOGLE_CLIENT_ID`, `ZIM_HUB_GOOGLE_CLIENT_SECRET`, `ZIM_HUB_GOOGLE_REDIRECT_URL`. Bundled into an optional `GoogleOAuthConfig`. Empty strings count as "unset".

**main.rs**: builds `AuthState::from_config(...)` after the identity store opens. If no Google config → logs an info line ("/login renders a not-configured page") and skips. `AppState.auth: Option<AuthState>`.

**Cargo.toml**: enabled `signed` feature on `tower-cookies = "0.10"` (the signed-jar API requires it). Added `base64` and `reqwest` back as direct deps (reqwest is needed by `oauth2`'s `request_async` helper).

**Templates** (`templates/pages/auth/`):

| File | Use |
|---|---|
| `login.html` | "Google OAuth is not configured" status card — only rendered when env vars missing. |
| `error.html` | Callback error page with a "Try again" link to `/login`. |

### M2b is one outstanding piece (call out)

Currently the callback handler stubs `sub` by slicing the access-token. To get the real Google `sub`, the callback needs to:
1. Request the `id_token` from Google (already in the token response — needs feature-flag `oidc` on oauth2 OR a custom `extra_token_fields`).
2. Verify it against Google's JWKS (`jsonwebtoken` is already in deps for this).
3. Extract `sub` + `email` claims.

That's ~50 LOC; I can land it as M2b in the next tick. Wanted to ship M2 with a working session round-trip first so M3 (enrolment) has something concrete to build on.
