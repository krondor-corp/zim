## Goal
Make zim-hub runnable with one command and a clear dev loop. Right now `cargo run -p zim-hub` works, but there's no Makefile target, no hot reload, no env-var defaults, no bin script, no documented port mapping. User feedback: "i have no clue how to even start a dev server."

Pattern reference: pack's `make dev` (hot reload via `cargo watch`, env-injected, prints "Starting on http://localhost:N" before exec). zim-hub's version doesn't need vault/db setup (yet) — just the runnable shape.

## Acceptance
- [ ] Root `Makefile` gains a `hub` (or `hub-dev`) target that starts zim-hub with hot reload and a printed URL.
- [ ] `cargo watch` invoked with `-w crates/zim-hub` (so template/Rust changes trigger rebuild).
- [ ] Env defaults set in the Makefile invocation: `ZIM_HUB_LISTEN=127.0.0.1:8080` (or chosen default), `RUST_LOG=zim_hub=info,tower_http=debug` or similar sensible dev defaults.
- [ ] `bin/hub` (or similar) shell wrapper if it makes the Makefile cleaner — optional.
- [ ] `.env.example` at repo root listing the env vars zim-hub reads (current + future OAuth/SQLite keys reserved as comments).
- [ ] `crates/zim-hub/README.md` updated: replace "How to run" with `make hub` as the canonical command; keep `cargo run -p zim-hub` as the fallback.
- [ ] No tmux requirement (pack's `make dev` is single-process; ours should be too for now).
- [ ] Verify the workflow by running `make hub`, opening `http://localhost:8080/`, editing `templates/pages/index.html`, confirming auto-reload.

## Out of scope
- DB setup (no state yet).
- Vault / secrets (later, with auth).
- Multi-process orchestration (single binary for now).
- Documentation in `wiki/` — that's T-014 (thing4).
