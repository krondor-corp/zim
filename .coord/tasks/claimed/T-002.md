## Goal
Design and scaffold a new `zim-hub` crate as the read-only mirror gateway. Pack-aesthetic for folder layout, file naming, and overall web UI feel. Stack: axum + askama + Datastar (vendored single JS, no toolchain), server-rendered + SSE, Google sign-in. **Datastar** (not HTMX) for hypermedia — see "Diverge from pack" in `broadcast/20260524T015636Z-pack-design-language.md`. Optional future: Milkdown-style **non-collaborative** editor surface (no Yjs).

Architectural patterns from pack (runtime::Service, struct-patch, Apalis, MCP, handler-per-file under views/actions) are **inspiration, not requirements**. Adopt whatever fits naturally; the design call is yours.

Constraints:
- **Multi-tenant (GitHub-for-buckets)**: one hub serves many Google-authenticated users. v1 unit = individual user. Org/team groupings = v2.
- Parity target is current desktop feature set (functional, not UI-identical).
- SQLite for state (no Postgres — see `broadcast/20260524T015636Z-pack-design-language.md`).

## Acceptance
- [ ] Target crate/module layout for `zim-hub` is documented. Pack-aesthetic folder shape encouraged but not mandated; the daemon-internal pattern set is the designer's call.
- [ ] Read-only mirror API surface specified (bucket tree / blob / history routes per thing3's parity checklist).
- [ ] Decision recorded on whether to adopt: Apalis (background jobs), MCP endpoint, runtime::Service, struct-patch. Each is "yes / no / later" with one-line rationale — not all-or-nothing.
- [ ] References `https://github.com/krondor-corp/pack` (aesthetic), `https://github.com/amiller68/thumbs-up`, `https://generic.krondor.org/` (secondary).
- [ ] Parity matrix maps current desktop features to zim-hub routes/APIs (use thing3's `.coord/agents/thing3/drafts/zim-hub-parity-checklist.md` as input).
- [ ] Workspace model is multi-tenant: schema namespaced by `google_sub`, route gating per user, no cross-user data leakage.

## Out of scope
- Full production OAuth implementation.
- Final UI styling decisions.
- Org / team / cross-user sharing (v2).
- WASM client (reserved for v2; v1 is server-rendered + SSE per thing3's plan).
- Yjs / collaborative editing.
- Any "migration from existing daemon" plan — clean break, see broadcast 20260524T014147Z.
