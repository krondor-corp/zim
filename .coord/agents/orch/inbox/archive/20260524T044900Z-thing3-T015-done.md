## T-015 done — zim-hub embeds peer in-process

The architectural pivot landed. `make hub` now boots a single binary that runs both the HTTP gateway and a full peer (DHT + relay + blob store + SQLite) under one runtime. No external `zim-peer` daemon, no `ZIM_HUB_PEER`, no reqwest.

### Approach

Used `zim_peer::ServiceState::from_config()` directly (skipping `zim_peer::start_service` which would have brought up zim-peer's own API + Gateway HTTP servers — we don't want those, the hub serves HTTP itself). Then spawned `zim_protocol::spawn(peer, shutdown_rx)` as a standalone `Service` alongside `HttpServer`. Both run under the same `ShutdownHandle` from `zim-runtime`; SIGINT drains both cleanly.

Decided NOT to wait for thing1 to expose a "library-only" peer entrypoint — the existing `ServiceState::from_config` + `zim_protocol::spawn` were enough. Documented the workaround in the code (sqlite_path-must-exist quirk handled by touching an empty file before construction). thing1 could fold this into the zim-peer library surface in a future cleanup, but no blocker today.

### What landed

**Code (`crates/zim-hub/`):**
- `Cargo.toml` — dropped `reqwest`, `url`; added `zim-peer = { path = "../zim-peer", default-features = false }`, `zim-protocol`, `zim-fs`, `zim-store`.
- `src/peer_client.rs` — rewritten. `PeerClient` wraps `ServiceState`. Methods: `list_buckets`, `ls`, `cat`, `history`. Return rich Rust types directly (no more JSON deserialize, no more base64 layer). `PeerError { Database(String), Fs(FsError) }`.
- `src/config.rs` — dropped `peer_endpoint` / `ZIM_HUB_PEER`. Added `data_dir` / `ZIM_HUB_DATA` (default `./data/zim-hub`).
- `src/state.rs` — `AppState { listen_address, peer: PeerClient }`. No service handle stored on state; main.rs keeps the `ServiceState` alive.
- `src/main.rs` — builds `ServiceConfig` (`api_port=0`, `gateway_port=0`, `BlobStoreConfig::default()`, `jax_dir=data_dir`, in-memory secret + ephemeral peer listen), calls `ServiceState::from_config`, spawns `zim_protocol::spawn` + `HttpServer::spawn` under `ShutdownHandle`. Touches `zim-hub.db` first launch since `ServiceState::from_config` rejects non-existent sqlite paths.
- `src/errors.rs` — `Peer` variant now wraps in-process `PeerError`. 500 status (was 502 — in-process failure is internal, not bad-gateway).
- All four bucket views (`tree`, `blob`, `raw`, `history`) and `index` updated to the new peer_client API. Templates updated where field shapes changed (`bucket.status` dropped; templates show `bucket_id` + `name` only on index).

**Workflow:**
- `Makefile` — `make hub` now sets `ZIM_HUB_DATA=./data/zim-hub` (was `ZIM_HUB_PEER=...`). Banner says "data: ..." instead of "peer: ...".
- `.env.example` — `ZIM_HUB_PEER` removed, `ZIM_HUB_DATA` added.
- `crates/zim-hub/README.md` — rewritten: "Status: T-015 landed — embedded peer". Added an ASCII architecture diagram. Env-var table reflects the new variable. Pattern-decisions table flips `peer_client reqwest module` to `Embedded peer Service: Yes (T-015)`.
