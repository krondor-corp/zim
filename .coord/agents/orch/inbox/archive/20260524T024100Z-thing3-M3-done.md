## M3 done — zim-hub now renders content

Wired `src/peer_client.rs` (reqwest, read-only methods only) against zim-peer's `POST /api/v0/bucket/{list,ls,cat,history}` surface, plus four new bucket routes with Askama templates.

**Layout (handler-per-file split now kicked in for the bucket area):**

```
src/peer_client.rs                                          (new — reqwest client + types)
src/http/html/bucket/
├── mod.rs                                                  (router)
└── views/
    ├── mod.rs                                              (breadcrumb helper)
    ├── tree.rs        — GET /b/{id}                       (alias /b/{id}/tree)
    ├── tree.rs        — GET /b/{id}/tree/*path
    ├── blob.rs        — GET /b/{id}/blob/*path
    ├── raw.rs         — GET /b/{id}/raw/*path             (raw bytes, inline)
    └── history.rs     — GET /b/{id}/history
templates/
├── pages/index.html                                        (rewritten — lists buckets)
├── pages/bucket/{tree,blob,history}.html                   (new)
└── partials/breadcrumb.html                                (new)
```

**Route shape exactly matches the parity checklist** (`/b/{id}/tree/*`, `/b/{id}/blob/*`, `/b/{id}/raw/*`, `/b/{id}/history`). `Editor`/`SharePanel`/`Logs`/`Mounts` remain intentionally absent per the parity matrix.

**API client decisions:**

- Mirrors zim-peer's request/response shapes as zim-hub-local serde structs. **No cargo edge from zim-hub to zim-peer.** Hub talks to peer over HTTP only — never imports its types. Shape duplication is bounded (~70 LOC) and decouples build graphs.
- `Link` fields deserialize as `serde_json::Value` (don't need the structure in v1 — `history.link_hash` is already `String` for display purposes).
- New env var `ZIM_HUB_PEER` (default `http://127.0.0.1:3001`).

**Graceful offline UX:** if the peer is unreachable, `GET /` renders a friendly status card with the peer URL and the underlying error message — no 5xx, no crash. Bucket routes return 502 Bad Gateway with the upstream error in the body (matches the `Error::Peer → BAD_GATEWAY` mapping I added to `errors.rs`).

**Verified live** (against a non-running peer on `:39999`):
- `GET /` → 200, renders "Peer at ... is not reachable" status card.
- `GET /b/{id}/{tree,blob,history}` → 502 with upstream error.
- `GET /_status/livez` → `ok` (independent of peer, as expected).
- SIGINT drains gracefully.

**Caveats:**

1. **No live-peer integration test yet.** The smoke test above runs against an unreachable peer. To exercise the green path against a real peer would need either a fixture harness or a manual two-process test (run `zim-peer`, then `zim-hub`, then curl). Suggested follow-up: add a `tests/peer_stub.rs` that boots a mini-axum mock of the four endpoints. Small task, ~100 LOC.
2. **Blob viewer is text-only in v1.** Mime types starting with `text/` or in a small whitelist (json/xml/yaml/javascript/toml) render as a `<pre><code>`. Everything else shows a "binary content" notice with a link to `/raw/*path`. Image/audio/video inline rendering can land in a follow-up.
3. **`/b/{id}/published` route from the parity checklist is NOT in M3.** That route is gated on T-008's per-file/folder publication scheme. Once T-008 lands, the route + the tree-filter behavior wire up at the same time.
4. **Snapshot browsing (`/b/{id}/at/{link_hash}/...`) is NOT in M3.** Same templates would render it — just needs the `at` param threaded through the handlers. Trivial follow-up.
