## Goal
Remove zim-hub's dependence on a running external `zim-peer` daemon. zim-hub spawns the peer services in-process as a `Service` (per the runtime::Service trait) and calls them directly from handlers. No reqwest, no `ZIM_HUB_PEER` env var, no localhost HTTP roundtrip.

User-visible target: `make hub` boots zim-hub, opens `/`, browses buckets. No "Start zim on this host" error. No second process.

## Acceptance
- [ ] `crates/zim-hub/src/peer_client.rs` rewritten (or replaced) — methods call in-process peer services directly. No `reqwest` for the bucket-read path.
- [ ] `ZIM_HUB_PEER` env var deleted from config / .env.example / Makefile / README. `make hub` is single-process.
- [ ] zim-hub `Cargo.toml` gains workspace deps on the crates exposing the peer surface (`zim-protocol`, `zim-fs`, `zim-store`, `zim-crypto` — whichever the in-process API needs).
- [ ] zim-hub's `main.rs` / `state.rs` spawns the peer Service alongside `HttpServer` under the same runtime. Both shut down cleanly on SIGINT.
- [ ] `make hub` boots → `GET /b/{id}` works against a local data store (path/dir to be decided; document in README).
- [ ] All four cargo checks green workspace-wide.
- [ ] README + `wiki/_docs/local-development.md` updated to reflect single-process workflow.

## Out of scope
- Deleting `crates/zim-peer` (it stays as the headless daemon).
- T-008 per-file/folder publish surface (consumed by this work but designed/built elsewhere).
- zim-wasm wiring (M4a, separate).
- Auth / OAuth (M5, depends on T-001).

## Coordination

- **thing1** owns `zim-peer` / `zim-protocol` / `zim-fs` / `zim-store`. The peer services need a clean "spawn into a runtime" entrypoint that zim-hub calls. If the current code only exposes a binary-bound API, ask thing1 to add a library-shaped entrypoint. Likely lands as part of T-007a (Service trait adoption + runtime extraction).
- **T-007a** is the natural enabler — both zim-peer (binary) and zim-hub (binary) use the same `Service` trait to spawn the same peer-side services. T-015 may need to wait for T-007a to land, or you may need to define the library surface yourself and coordinate the import.
