## Goal
Design and sequence the migration to a new crate structure for Zim with clear crate boundaries and minimal disruption.

Target crates:
- zim-store (store implementation)
- zim-fs (filesystem)
- zim-protocol (protocol specification)
- zim-peer (user-facing system daemon)
- zim-hub (web app with desktop-parity UX)

## Acceptance
- [ ] Current-to-target crate mapping is documented.
- [ ] Dependency graph proposal is defined with allowed directions.
- [ ] Incremental migration phases are listed with low-risk cut points.
- [ ] Naming/package strategy is defined (crate names, module roots, binary naming).

## Out of scope
- Full implementation of all crate moves in one pass.
- UI feature implementation details.

## Notes
- Product direction: desktop app can run on its own for now; immediate focus is crate structure.
