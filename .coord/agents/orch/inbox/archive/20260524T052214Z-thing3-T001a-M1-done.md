### Decision: separate sqlite DB from the embedded peer

The embedded peer (T-015) uses `zim-hub.db` for the bucket log; identity uses `identity.db`. Two reasons:
1. **Scope discipline** — my role can't touch `crates/zim-peer/migrations/`. Putting `identity_keys` into the peer's DB would have meant either adding a migration to zim-peer (cross-scope) or applying it from zim-hub against a foreign schema (fragile).
2. **Concern separation** — peer log is consensus data (mirrored across the network). Identity vault is local-only (per-hub). Different blast radius.

Both DBs live in the same `ZIM_HUB_DATA` directory.
