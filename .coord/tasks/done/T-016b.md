## Goal
Implement T-016's wire-protocol gating in `zim-protocol`. See T-016 `## Proposal (20260524T044750Z thing5)` for full design.

## Acceptance
- [ ] `mount_for_read` rewrites to dispatch on `Manifest::classify_peer(pk)` instead of `PrincipalRole::Mirror` branch.
- [ ] JAX-protocol message verbs gated by `PeerType`:
  - Owner: manifest + log-head + everything.
  - Mirror: manifest + log-head + blobs reachable from `published_set` (T-008's surface).
  - Anonymous: manifest only (per T-016 Decision 3).

- [ ] `cargo build/test/clippy/fmt` all green.

  - ◯ JAX-protocol per-verb gating: only Ping exists today (low-stakes connectivity check, OK for any peer-type). When more verbs land (T-008b fetch endpoints, future log-head fetch, etc.), they should call `peer.classify_remote_peer(bucket_id, sender)` themselves and reject inappropriate access. Hook point is documented; concrete per-verb impls will land WITH the new verbs.
  - ◯ **Known gap (deeper redesign, not in T-016b)**: Mirror peers currently get full blob-fetch access for any blob this node holds, not just blobs reachable from the requested bucket's `published_set`. iroh-blobs does not expose per-request hooks for per-blob filtering at the protocol layer; per-blob filtering would require either a custom protocol layered on raw blob fetches or a fork of iroh-blobs that exposes the hook. Documented in the `GatedBlobsHandler` doc comment. Should spawn as `T-016b-followup` or fold into a future zim-protocol design pass.
